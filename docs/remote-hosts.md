# Remote hosts

Spaces are grouped by destination (host and Herdr session) in the sidebar whenever more than one destination is open. Click a Space to switch directly to it. The disclosure arrow only expands or collapses the group; its **+** creates a Space on that destination. The current host and session also appear in the status bar when the sidebar is hidden.

Choose **Manage Remote Hosts…** in the app's actions menu, or in the session picker at the bottom of the sidebar. Local sessions remain available through that picker. **Back to Previous Context** returns to the previous destination and Space, including its selected tab and pane. Its default shortcut is the configured prefix followed by Backspace; change it in the wooloo section of the shortcut settings. This app-only shortcut is stored separately from Herdr's configuration.

Add an OpenSSH target (`user@host`, an alias from `~/.ssh/config`, or `ssh://user@host:port`), an optional label and a remote Herdr session. wooloo runs `herdr machine add --remote-session …`; Herdr prepares the remote server and persists its own machine profile. No separate wooloo host database is created. SSH keys, ports and proxies follow OpenSSH configuration.

The manager also delegates rename, enable, disable and remove to `herdr machine`. Disabled hosts remain visible in the manager but are omitted from the picker. Removing a profile does not delete remote files or stop its sessions.

Selecting a Space changes the visible destination for terminal panes, agents, file explorer, Git operations, host information and quotas. Each window keeps its own selection. The saved profile's remote session is used explicitly. A slow Space creation opens its result only if the user has not navigated elsewhere while it was running. Rename and close confirmations retain their original connection and are rejected if that connection was invalidated.

Metadata subscriptions and private SSH bridges are shared between windows for each destination. Background destinations use the JSON API only: they do not open a terminal endpoint, poll pane text or send input, focus or resize. Each window attaches a terminal surface only for its visible destination. Switching away retains metadata and selection, so returning does not repeat the API connection setup. Agents remain scoped to the visible destination in this release.

A disconnected destination retains an explicitly marked last-known Space list. Mutations stay disabled until fresh metadata arrives. Switching hosts disables terminal input until a matching fresh surface is ready; ordinary tab switches on an established terminal retain their input routing. A disabled or removed selected host remains visible and disconnected until the user chooses another destination. It never silently routes actions to Local.

The app uses private local sockets and OpenSSH channels to Herdr’s `remote-api-bridge` and `remote-client-bridge`. Herdr must already be installed and prepared on the remote host through the machine manager. Selecting a host does not install software. A failed remote connection stays on that host and shows an error; it never falls back to issuing commands locally. Switching away closes that window's terminal attachment, leaving the metadata subscription, server, shells and agents running. Closing the last window using a destination releases its metadata connection and bridge.

Open documents, including unsaved edits, are scoped by profile, SSH target, session and Space. Changing a profile's SSH target creates a separate context; existing documents are imported from the earlier profile-only namespace only when their saved target matches. Import and backup ownership are committed atomically so two windows cannot claim the same dirty buffer. Returning to a host restores its documents without mixing identically numbered Spaces from different servers. Explorer location and focused panel are remembered per destination; search queries are cleared on a destination change. Herdr configuration editing is available for Local; remote configuration remains managed on its own host. Appearance and notification preferences remain app settings.

**Remote Access** follows the selected host and session. For a remote host it resolves the saved SSH alias, reads the remote account and public host keys, and shows a direct SSH QR for wooloo mobile. Review the phone-facing hostname and port, especially if the Mac uses a proxy, jump host or VPN. A publicly reachable SSH endpoint needs no Cloudflare tunnel. The tunnel controls appear for local sessions only.

To authorize the phone, paste its shared OpenSSH public key into Remote Access and choose **Review Authorization…**. The review identifies the key fingerprint, saved SSH target, actual account and absolute `authorized_keys` path. **Authorize Key** sends the public key over the existing authenticated SSH connection and grants SSH access to that remote account across its sessions. Existing entries and restrictions survive; a repeated key is not duplicated. This uses the account's `~/.ssh/authorized_keys`, without sudo or SSH daemon changes. The private key stays on the phone. A failed remote operation never falls back to writing on the Mac.

Preparation runs without a terminal and has a two-minute timeout. If SSH needs a password, host-key confirmation or other interactive authentication, first connect using SSH in Terminal, then retry. Herdr errors are displayed in the manager.

Validation uses a fake Herdr executable in `WorkspaceHerdrCommandTests`, plus isolated API and binary endpoint servers connected through a duplex subprocess bridge in `HerdrStoreTests`. The latter exercises executable discovery, session routing, Spaces, agents, terminal input, tab creation, failed connections and attachment cleanup. `WorkspaceDocumentStoreTests` covers unsaved documents across identically numbered Spaces on different hosts. Tests do not modify the user's saved machines.

The transport follows Herdr 0.9.3’s [saved SSH API and client bridges](https://github.com/herdrdev/herdr/blob/v0.9.3/src/remote/saved.rs).

Notifications are coordinated once per application and identify the destination as well as the pane. Clicking an alert reveals the corresponding terminal; it is acknowledged only when the frontmost window actually shows its fresh focused surface. Counts remain scoped to their destination even when server IDs coincide. Disconnect/reconnect establishes a new baseline rather than claiming to replay every transition missed offline.

Multi-host regression tests cover passive API connections, one shared metadata subscription across windows, independent selection, delayed creation, identical IDs in confirmations, cancellation before dispatch, remote capacity isolation, target changes, and atomic legacy-buffer import. They use fake API/terminal endpoints and SSH subprocess bridges, never the primary Herdr session.

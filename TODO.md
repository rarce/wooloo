## Terminal performance

On a 113×48 grid, arrival to draw takes about 0.8–1.5 ms at p50 and a keystroke reaches the draw in about 0.8 ms; the display then adds an estimated 12–15 ms at 120 Hz. Kitty images cost wooloo little. A tab switch draws in 7–13 ms, a two-pane split streams without dropped frames, and the stream thread no longer stalls under machine load. What remains is mostly Herdr's side and the display refresh.

Measure with `scripts/workspace-bench.sh`; see `docs/perf/README.md`.

- [x] Share SSH connections, load the repository once per refresh, and run git without the `/usr/bin/git` shim. A local refresh of a large repository dropped from 631 to about 200 ms, and over SSH from 1.8 s to about 0.8 s.
- [x] Batch the SSH commands of one refresh. Over SSH the listing runs as one remote script, and the Git bar's status and repository as another, which the repository panel shares (`WorkspaceFiles.gitBatch`): 9 SSH commands per refresh became 2, and a large repository's refresh dropped from 1041 to 283 ms against the OrbStack VM.
- [x] Fold the listing into the Git bar's script too, so a refresh is one round trip. The listing, the Git bar and the repository panel share one remote script (`WorkspaceFiles.remoteRefresh`), which also lists a folder outside a repository with `find`: a refresh over SSH is 1 command instead of 2, and took 175 ms instead of 283 ms in the large repository (64 instead of 81 ms in the small one), though under lower machine load than before. Each load alone now runs the whole script.
- [x] Run the commands of the SSH refresh script concurrently instead of one after another. Every command of a batch only reads and runs with `GIT_OPTIONAL_LOCKS=0`, so no `git status` takes `index.lock`; 100 rounds of the whole batch at once in a repository with a stale index, on this Mac and the OrbStack VM (`dash`), printed no lock error and the same status every time (Git's `status` also gives up its index write quietly when the lock is taken). The script starts the commands as background jobs and prints their sections in order once all finish; the root check still runs before the commands that need it. A refresh of the large repository over SSH took 192 instead of 210 ms at p50 against the OrbStack VM, where one SSH command cost about 110 ms under that load; the script alone took 49 instead of 59 ms on the VM and 215 instead of 332 ms on this Mac.
- [ ] Cap how many commands of an SSH batch run at once if small remotes suffer. A refresh starts about a dozen processes together, including two `git status` and two `git ls-files`, so a large repository's index is read into memory several times at once, which a remote with one core or little memory may feel more than the saved milliseconds. Measure a refresh on such a remote before choosing a limit.
- [x] Cut the `git rev-parse` calls that `listing` and `repository` each make for the same root. The root is kept for 2 s like the repository (`gitRoots`), so a local refresh runs 9 processes instead of 10.
- [x] Profile syntax colors for a large diff (`parse-big-diff-highlighted`). Each side went about 40 % to tree-sitter parsing, 35 % to the highlight query (half of that in SwiftTreeSitter splitting capture names) and 25 % to a linear search for each capture's line. Captures now find their line by binary search and are sorted instead of hashed. Only removed lines take colors from the old file, so it is skipped when nothing was removed, queried only at those lines, and parsed by editing the new file's tree so tree-sitter reparses only around the changes (about 5× faster for JavaScript and Rust, 1.2× for Swift, whose grammar seldom reuses nodes, no gain for Go). The diff view adds the colors to the patch it already parsed instead of parsing it again. The benchmark (a third of 5,000 lines changed) dropped from about 195 to 150 ms at p50, and three one-line edits in the same file from about 180 to 105 ms. Parsing the two sides on two threads was slower than one after the other, so they stay serial. Parsing itself, now about half the time, is what remains.
- [x] Log SSH's exit status and stderr. Failed SSH commands go to the unified log (subsystem `dev.wooloo.workspace`, credentials in URLs removed) and to `proc` events as `status`. An expiring `ControlPersist`, a master killed between commands, and 14 concurrent sessions all worked against the OrbStack VM. A master that dies while a command runs gives that command exit 255 with its output complete and nothing on stderr, which matches the failure seen once.
- [x] Stop blocking Swift's cooperative threads with processes. Git, file, SSH, host-stats, quota and Herdr socket loads, and the Herdr event stream, now run through `BlockingWork.run`, which gives each one a thread of its own and resumes the caller with a continuation, so slow SSH loads (5–300 s timeouts) and `SharedLoads` waits no longer hold the cooperative pool. At most `BlockingWork.limit` (the core count, from 4 to 8) run at once, which keeps an SSH Space under sshd's default `MaxSessions` of 10 on the shared ControlMaster; the rest wait suspended, and a cancelled caller never starts. The event and surface streams, which block while connected, take no slot. Tests hold every slot and check that waiting calls leave the pool free, that no more than the limit run, and that cancelled calls never start. `HerdrRuntimeService`, an actor, still runs `launchctl` and its socket checks on the pool during setup.
- [x] Enforce the rule in the blocking APIs instead of at each call site. The synchronous entry points that block (`WorkspaceFiles`, `SharedLoads.value`, `HerdrSocket`, `HerdrEventStream.run`, the host-stats, quota, config and remote-access probes, and the image, PDF and search helpers built on them) are `@available(*, noasync)`: calling one straight from async code is a warning, an error in the Swift 6 language mode, while the synchronous closures passed to `BlockingWork.run` stay allowed. The check stops at a synchronous function or closure in between, such as a `Result { … }` in a `Task`, so `BlockingWorkLoadTests` also runs many Git bar loads against an SSH machine that hangs and checks that only `BlockingWork.limit` run, the rest wait, and both the cooperative pool and the main actor stay free; that test fails, rather than hangs, when the load runs on the pool. `HerdrRuntimeService` and `WorkspaceSessionPersistence` run on serial queues of their own (custom actor executors), keeping their ordering without taking a slot. The pane-text fallback poll and the `HostStats` loop run on a `BlockingWorker`, a private serial queue per loop, instead of a new thread per read.
- [ ] A per-machine limit on blocking work, so local loads run while an SSH machine is saturated. The closures passed to `BlockingWork.run` do not say which machine they reach, so every call site (about 30) would have to name it, and one that forgot would land in the local pool and let a machine exceed sshd's `MaxSessions`. Async entry points on `WorkspaceFiles` that take the location, and pick the limit from it, would make that impossible to get wrong.

## Editor

- [x] Multiple cursors: ⌥⌘↑/↓ keep the goal as a display column (`DisplayColumns`), expanding tabs to the editor's tab width and counting wide characters and emoji as two columns, so they no longer shift it. ⌥⌘↓ from a selection spanning lines adds below its end, not inside it.
- [ ] Multiple cursors: display columns assume a wide character is exactly two cells, but the editor draws CJK and emoji with a fallback font whose advance is not a whole number of cells (with the 13 pt system monospaced font, about 1.6 for 日 and 2.4 for 👍), and places tab stops in points. After several wide characters, or a tab behind them, the added cursor can sit a column or two off the one above. Keeping the goal as an x position from the editor's layout would match exactly, but needs lines that are not laid out yet.
- [x] Multiple cursors: a run of ⌥⌘↑/↓ keeps the first selection's display width with its goal column, so a shorter part added on a short line no longer narrows the lines after it. Any other selection change starts a new run.
- [x] Terminal popup titles (`HerdrSurface`) gave CJK and emoji one cell instead of two: `wcwidth` answers -1 for anything non-ASCII in the app's C locale. They now take their width from `DisplayColumns.width(of:at:tabWidth:)`, as Herdr's own chrome does with `unicode-width`, and leave out what draws nothing (controls, tabs, a lone combining mark). Herdr sends only the title text, and wooloo draws the popup chrome itself, so the content rectangle is unaffected. Sizing a title costs about 0.5 µs more per drawn frame while a popup is open; `scripts/terminal-bench.sh` and `scripts/terminal-e2e.sh` do not open popups.
- [ ] Terminal popup titles: `DisplayColumns` still differs from Herdr's `unicode-width` 0.2 on rare clusters (checked against the crate): a lone regional indicator (2, Herdr 1), U+FE0E after an emoji without a text variation such as 😀 or 🈁 (1, Herdr 2), a keycap or ZWJ without U+FE0F (`1⃣` 2, Herdr 1; `🏳‍🌈` 2, Herdr 3), halfwidth kana with a sound mark (`ｶﾞ` 1, ratatui 2), Thai SARA AM and lone Hangul vowels. The editor shares the function and draws some of these differently from a terminal, so a fix should be terminal-only or settled for both.
- [x] Multiple cursors from the rest of Zed's set: ⌃⌘D adds the previous occurrence (⌘K ⌃⌘D skips to it), and is in the command palette as Add Previous Occurrence to Selection. Option-drag selects a block of display columns, one selection per line; as in Zed, a line shorter than the block's left column is skipped and one ending inside it is selected to its end. Like the editor's own drag, the block goes on growing while the view scrolls under a mouse held past its edge or a scroll wheel turns. ⌘U also returns from clicks (a click and its drag are one step; a later drag after a click that changed nothing is a step of its own) and from navigation keys (a run of arrows, Home, End and Page Up/Down is one step), for up to 100 steps; edits still clear it.
- [ ] Multiple cursors: macOS takes ⌃⌘D for Look Up before the app sees it, so the key works only with that shortcut turned off (`defaults write com.apple.symbolichotkeys AppleSymbolicHotKeys -dict-add 70 '<dict><key>enabled</key><false/></dict>'`, then log out); the command palette works either way. Not checked on a Mac with Look Up off. Consider a second key that macOS leaves alone.
- [x] Multiple cursors: ⌘U records every selection change that is not part of an edit, as Zed does: ⌘A, find matches, Go to File and search reveals, and selections set in code are a step each, and Emacs-style navigation keys (⌃N, ⌃P, ⌃A, ⌃E, ⌃V…) join arrows in one run of navigation keys. - [x] Multiple cursors: with line wrapping on, an Option-drag block follows the display rows on screen, as in Zed: columns count from each row's start (`MultiCursor.columnSelection(in:rows:…)`, rows from the editor's line fragments), so a block over wrapped lines is rectangular.
